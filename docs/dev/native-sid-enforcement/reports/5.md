# Task 5 report: populate the NFS request credential

## Status

DONE.

## Summary of the deviation from the brief (per your ruling)

The brief's Step 3 stored the borrowed pointer directly:
`req->cred.sids = chimera_vfs_cred_sids_lookup(...)`. Per your ruling, this
is wrong -- `chimera_vfs_cred_sids_lookup()`'s result is pinned by nothing
and is only valid until this thread's next resolve or warm (see the
lifetime contract at the top of `src/vfs/vfs_cred_sids.h`). A second
request landing on the same VFS thread and warming a different credential
could evict the entry and leave `req->cred.sids` dangling into a later
authorization check.

Implemented instead: copy the looked-up set into request-owned storage,
the same shape Task 4 used for the SMB session
(`chimera_smb_session_sids_cb` in `src/server/smb/smb_proc_session_setup.c`).

## Files changed

### `src/server/nfs/nfs_common.h`

1. Added `#include "vfs/vfs_cred_sids.h"` (for
   `chimera_vfs_cred_sids_lookup()` / `chimera_vfs_cred_sids_warm()`).

2. Added a new field to `struct nfs_request`, right after `orig_cred`:

   ```c
   /* Backing storage for cred.sids and orig_cred.sids when the per-thread
    * resolver has a SID set for this caller (see chimera_nfs_map_cred_req).
    * A looked-up set is only borrowed from the thread's cache and can be
    * evicted by another request's resolve, so it is copied here rather than
    * pointed to directly; this request owns the copy and outlives every
    * struct copy of cred it hands out (fh decode, putfh/putrootfh/restorefh).
    * Unused (and cred.sids is NULL) when the caller is unresolved or the
    * credential has been squashed to the export's anonymous identity. */
   struct chimera_vfs_cred_sids      cred_sids;
   ```

   `struct nfs_request` is pooled per thread (`thread->free_requests`,
   `nfs_request_alloc`/`nfs_request_free` around `nfs_common.h:515-563`), so
   the ~1.3 KB of `chimera_vfs_cred_sids` is amortized over the pool
   high-water mark, not paid per operation -- matching the brief's framing
   and your ruling.

3. Rewrote `chimera_nfs_map_cred_req()`:

   ```c
   static inline void
   chimera_nfs_map_cred_req(
       struct nfs_request          *req,
       const struct evpl_rpc2_cred *rpc_cred)
   {
       const struct chimera_vfs_cred_sids *sids;

       chimera_nfs_map_cred(&req->cred, rpc_cred);

       sids = chimera_vfs_cred_sids_lookup(req->thread->vfs_thread, &req->cred);

       if (sids) {
           req->cred_sids = *sids;
           req->cred.sids = &req->cred_sids;
       } else {
           chimera_vfs_cred_sids_warm(req->thread->vfs_thread, &req->cred);
       }

       req->orig_cred = req->cred;
       req->sec_bit   = chimera_nfs_sec_bit(rpc_cred);
   } /* chimera_nfs_map_cred_req */
   ```

   On a cache hit the set is copied into `req->cred_sids` and `cred.sids`
   points at that copy (request-owned, stable for the whole request). On a
   miss, `cred.sids` stays NULL (already the case coming out of
   `chimera_nfs_map_cred()`, see below) and a background warm is kicked so
   the *next* request from this caller on this thread is enforced --
   unchanged fail-closed behavior for the first request, matching the
   brief's documented contract.

   Confirmed `req->cred.sids` is always NULL immediately after
   `chimera_nfs_map_cred()`, before the lookup: every branch of
   `chimera_nfs_map_cred()` (AUTH_SYS via `chimera_vfs_cred_init_unix`,
   AUTH_NONE/unknown via `chimera_vfs_cred_init_anonymous`, RPCSEC_GSS via
   `chimera_nfs_gss_map_principal()`) bottoms out in one of
   `chimera_vfs_cred_init_unix` / `_init_attr` / `_init_anonymous`
   (`src/vfs/vfs_cred.c:85-141`), all of which set `cred->sids = NULL`. So
   there is no stale pointer from a previous occupant of a pooled
   `nfs_request` leaking through.

## Squashing drops the SIDs -- how confirmed

`chimera_vfs_cred_init_anonymous()` (`src/vfs/sdk/vfs_cred.h:132-141`) sets
`cred->sids = NULL` unconditionally. `chimera_nfs_squash_cred()`
(`nfs_common.h`) calls it for both `SQUASH_ALL` (every caller) and
`SQUASH_ROOT` when `uid == 0`; `SQUASH_NONE` is a no-op and leaves
`cred.sids` untouched (correct: nothing was squashed, so the caller's own
SIDs still apply). This was true before my change (Task 1 already wired
`init_anonymous` to null `sids`) -- Task 5 only had to confirm that nothing
it added bypasses `chimera_nfs_squash_cred()` or re-sets `sids` after a
squash. Traced every call site above and confirmed none does.

I did not add a new automated test specifically for "squash drops SIDs"
because `test_fh_security.c::test_squash()` already exercises
`chimera_nfs_squash_cred()` directly (ROOT/ALL/NONE, with supplementary
group clearing asserted) and Task 1's `ace_applies()`/cred-sids machinery
is exercised by `vfs_cred_sids_test.c`; wiring a new end-to-end SMB/NFS ACE
test that spans squash + SID resolution was out of scope for this task's
brief and not requested. Flagging this as a place the reviewer may want
more coverage (see Concerns).

## Uncrustify quirk encountered (informational)

My first draft of the `cred_sids` field comment used the phrase "cred.sids
/ orig_cred.sids" (with a bare `/`). Running `uncrustify --replace` on that
text produced a stable-but-inconsistent result: the comment's continuation
lines were indented one column left of every other multi-line comment in
the file (`    * text` instead of `     * text`), i.e. it passed the
pass-to-pass stability check but did not match the file's established
style. Rewording to "cred.sids and orig_cred.sids" (removing the bare `/`)
made uncrustify produce the expected 5-space-indented continuation,
matching neighboring comments. I'm noting this because it means
pass-to-pass stability alone is not sufficient evidence of "matches house
style" when a comment contains a stray `/` -- worth remembering for future
tasks in this codebase.
