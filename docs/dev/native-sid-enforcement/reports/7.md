## 1. Documentation edits

### `src/vfs/sdk/vfs_acl.h:92-99` (brief Step 1)

The `CHIMERA_PRINCIPAL_SID` comment said a SID principal "matches no caller
during access evaluation," which stopped being true once Task 1
(`0f7b7424`) made `ace_applies()` match it against the caller's own resolved
SIDs. Replaced with the brief's exact text:

```c
    /* A native Windows SID the identity layer could not map to a uid or gid.
     * It is stored and marshalled verbatim so the ACE round-trips losslessly
     * (as NTFS keeps an ACE for a departed domain user).  During access
     * evaluation it is matched against the caller's own resolved SIDs (see
     * chimera_vfs_cred_sids), so a descriptor carrying only bare domain SIDs
     * still enforces; a SID that names no caller we know matches nobody, and
     * it bears on no POSIX mode class either way. */
    CHIMERA_PRINCIPAL_SID     = 3,
```

## 2. Quint / `ext/specs` finding (brief Step 3 -- report only, no code change)

```
grep -rln "acl\|principal\|sid" ext/specs/ 2>/dev/null
```
matched several `.qnt` files, but every hit is a false positive against this
feature:

- `posix_fs.qnt:19` -- the string "ACLs" appears only in a comment
  explicitly disclaiming scope: *"Neither module claims to exhaust the
  server's real VFS, which is a richer NFS/SMB hybrid (NFSv4 ACLs, share
  modes, streams); each models exactly what its protocol can observe."*
- `nfs3.qnt:73` -- "principals" refers to the three test credentials
  (`ROOT_CRED`/`ALICE`/`BOB`), each a plain `{uid, gid, gids}` record, not an
  ACL/SID principal.
- All the `sid`/`Sid` hits across `nfs4.qnt`, `nfs4_state.qnt`,
  `nfs4_ops.qnt`, `nfs4Test.qnt`, `posix.qnt`, `posixTest.qnt`,
  `posix_state.qnt` are NFSv4 **stateid** (`Sid`, `SidKind`, `SidSel`,
  `SidRef`) -- open/lock/deleg/layout state identifiers -- or word fragments
  (outside, consider, beside, reside, decides). None is a Windows security
  identifier.

**Finding: the quint specification does not model ACL evaluation at all.**
Access control in the model is exclusively the plain Unix credential
(`Cred = {uid, gid, gids}`) compared against POSIX mode bits (with an
`P_OWNER_OVERRIDE` flag for the NFS owner-override behavior). There is no
ACL, DACL, ACE, or principal-matching concept anywhere in `ext/specs/`, so
there is no existing structure to extend with a SID-principal case. Adding
ACL modeling to the spec is a larger piece of work than this task and was
not started, per the brief's own instruction for this exact case. This
should be noted in the pull request when the branch is eventually opened for
review, as the brief's Step 3 originally intended.
